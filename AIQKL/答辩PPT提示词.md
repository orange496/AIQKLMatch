## 第 3 页 · 项目背景与意义

- **页面内容**（3 个要点 + 一个痛点图/文字）：
  - 痛点：成绩数据存在数据库里，管理员/内部人员可**直接改数据库**，改了不留痕迹

  - 目标：让成绩**一旦录入就不可篡改**，篡改必被发现
- **讲解提示**：

## 第 6 页 · 核心技术一：区块链原理

- **页面内容**（画一个链式结构图，3~4 个区块用箭头连起来）：
  - 每个区块 = 数据 + 前一块哈希 + 自己哈希 + 随机数 nonce
  - 前一块哈希像"指纹"把区块串成链，**改任何一块，后面全部失效**
  - 工作量证明 PoW：哈希前 N 位必须为 0（本项目难度=3）
- **讲解提示**：
  - "区块链防篡改的本质是哈希链。每个区块都存了上一个区块的哈希值，就像一条用指纹串联的链条——改了中间任何一环，后面的指纹全对不上，篡改立即暴露。"

---

## 第 7 页 · 核心技术二：AI 异常检测

- **页面内容**（放 IsolationForest 的原理示意 + 特征列表）：
  - 算法：**IsolationForest（孤立森林）**，无监督，无需标注数据
  - 7 个特征：分数、学分、课程均分、学生均分、偏离课程均分、偏离个人均分、录入时间
  - 输出风险等级：low / medium / high，高风险自动打标 `HIGH_RISK_ANOMALY`
- **讲解提示**：
  - "AI 做的是'预警'而非'定案'——用孤立森林找出'明显偏离正常'的分数或深夜录入等异常行为，给出风险等级提示人工复核，和区块链的'防篡改'互补。"

## 第 8 页 · 数据库设计

- **页面内容**（两张表的结构图）：
  - `grades` 业务表：id、student_id、course、score、credit、hour、block_index、ai_risk、created_at
  - `chain` 区块链表：idx、timestamp、data(JSON)、prev_hash、nonce、hash

- **讲解提示**：

## 第 10 页 · 核心功能演示：防篡改闭环 ⭐

- **页面内容**（放 4 步流程的截图或箭头图）：
  1. 录入成绩 → 链上生成区块，返回哈希
  2. 篡改脚本把某区块分数改掉
  3. `GET /verify` → 返回 `valid: false`，并指出 `tampered_index`
  4. 修复脚本恢复 → 再验证 `valid: true`
- **讲解提示**：
  - "这是系统的核心演示：先录入，再用脚本篡改数据库，验证接口立刻报'第几块被改'，最后修复恢复。整个过程证明了'篡改必被发现'。"

## 第 11 页 · 关键实现一：区块链模块

- **页面内容**（放核心代码片段，高亮 3 处）：
  - `compute_hash()`：SHA-256 对区块内容求哈希
  - `mine()`：PoW 挖矿，循环 nonce 直到哈希前 N 位为 0
  - `verify()`：全链逐块重算哈希 + 校验 prev_hash 是否连续
- **讲解提示**：
  - "区块链模块只有一百多行，核心是三个方法：算哈希、挖矿、验证。验证时对每一块用存储的 nonce 重新算哈希，只要和数据里存的哈希不一致，就判定被篡改。"

## 第 14 页 · 开发中遇到的问题与解决

- **页面内容**（两个问题 + 解决，配代码对照）：
  - 问题1：`np.bool_` 类型无法 JSON 序列化 → 上链时崩溃
    - 解决：`bool(label == -1)` 转成 Python 原生类型
  - 问题2：正则修复误伤 `ai_result` 内层 score 字段 → 修复后哈希仍对不上
    - 解决：改用 JSON 解析，只改顶层 score，绝不触碰内层
- **讲解提示**：
  - "这两个 bug 都很有代表性：一个是 numpy 类型和 JSON 的兼容性，一个是正则全局替换误伤嵌套字段。解决过程让我对数据流和类型边界有了更深理解。"

## 附 · 演示小抄（现场演示时的关键命令）

```bash
# 启动
uvicorn main:app --reload
# 浏览器打开 http://127.0.0.1:8000/docs

# 录入成绩（示例）
curl -X POST "http://127.0.0.1:8000/grade" -H "Content-Type: application/json" \
  -d '{"student_id":"2023001","course":"高等数学","score":95,"credit":4,"hour":10}'

# 验证（核心）
curl "http://127.0.0.1:8000/verify"

# 篡改（另开终端）
python tamper.py     # 输入区块号 1，改成 99

# 再验证 → 应返回 valid:false, tampered_index:1
curl "http://127.0.0.1:8000/verify"

# 修复
python repair.py

# 再验证 → 应恢复 valid:true
curl "http://127.0.0.1:8000/verify"
```

> 演示顺序建议：**录入 3 条 → verify(true) → tamper → verify(false) → repair → verify(true)**，一气呵成，最能体现系统价值。
